# 边缘全量摘要上云与原始上下文缓存方案

适用范围：边缘节点与云端复核模块之间的数据协作。

目标：边缘保持本地快速执行；云端仍能获得完整的正常历史，并在调度器路由云端时取得触发包前后的高采样率原始上下文。

## 1. 基本原则

1. 调度器是唯一的云端路由决策方。边缘不因本方案改变本地实时推理和调度结果。
2. 每个数据包都上报轻量级边缘摘要；高采样率原始波形不全量上传。
3. 边缘先接收三路高采样率原始波形并写入环形缓存，再从同一包降采样生成低采样率分析数据；边缘特征提取只使用降采样数据。
4. 云端是唯一的正式数据库写入方；边缘只维护本地持久队列和原始数据缓存，不直接写云端数据库。

## 2. 每包全量摘要异步上云

1. 边缘每接收一个高采样率原始包，必须先完成“写入高采样率环形缓存 → 降采样 → 低采样率边缘校验、预处理和基础特征提取”。
2. 边缘完成当前包分析后，无论调度器选择本地还是云端执行，均生成一条 `EdgeFeatureSummary`。
3. 摘要至少包含：
   - `task_id`、`packet_id`、`device_id`、`sequence_number`、`timestamp_ns`；
   - `operating_context`；
   - `perception_quality`；
   - `features`：振动、两路电流和电流关系特征；
   - `edge_feature_extractor_version`、边缘模型版本、生成时间。
4. 摘要不携带高采样率 `values`。边缘将摘要写入本地持久发送队列，再异步批量发送给云端 `EdgeFeatureSummaryIngestion`。
5. 默认每 20 包或最多等待 1 秒发送一次；云端确认后删除本地队列项。网络不可用时保留并按 `sequence_number` 补传，禁止因网络失败影响本地诊断。
6. 同一 `(device_id, packet_id)` 的重传必须内容一致，支持云端幂等去重。

## 3. 边缘高采样率原始数据环形缓存

1. 边缘对每个设备保存振动、`phase_current_1`、`phase_current_2` 三路同窗口高采样率原始包，并按 `sequence_number` 和 `timestamp_ns` 建索引。
2. 默认缓存保留至少 60 秒；三路数据必须保留相同的 `sample_rate_hz`、`sample_count`、`start_timestamp_ns`、`end_timestamp_ns` 和 `packet_id`。
3. 环形缓存淘汰最早完整包，不得只删除三路信号中的某一路。
4. 调度器路由云端时，当前高采样率原始包随 `CloudReviewRequest` 上传；此前的普通包不主动上传原始波形。

## 4. 响应云端原始上下文请求

云端在校验触发包后向边缘发出 `RawContextRequest`，默认请求触发包前 10 包、后 10 包。

1. 已存在的前置包立即发送；当前包不重复发送。
2. 后置包尚未产生时，返回 `pending_context`，并在每个后续包生成后继续补传，直到补齐 10 包。
3. 若缓存已淘汰、指定序号不存在或三路包不完整，返回 `insufficient_context` 和缺失的 `packet_id` / `sequence_number`；不得使用非连续包替代。
4. 上下文补传使用与 `CloudReviewRequest` 相同的 `cloud_raw_packet` 结构，并保持纳秒时间戳、采样参数和身份字段不变。

## 5. 边缘本地状态与故障恢复

1. 摘要发送队列必须持久化；设备重启后继续补传未确认摘要。
2. 原始数据缓存可因重启丢失，但必须明确返回 `insufficient_context`，不能伪造“上下文完整”。
3. 云端重复请求同一上下文时，按 `(device_id, anchor_packet_id, before_packet_count, after_packet_count)` 幂等处理。
4. 云端只使用全量边缘摘要建立正常历史基线；云端复核结果是附加证据，不替换边缘摘要历史。

## 6. 验收标准

- 任意高置信度本地执行包，最终都能在云端 `edge_feature_history` 中查询到摘要。
- 触发云端复核后，可立即获得当前包和前置上下文；后置上下文补齐后，云端能将状态从 `pending_context` 更新为 `complete`。
- 缓存缺失时，云端结果为 `insufficient_context`，仅保留单包复核，不生成跨包 THD、聚合或高级分析。
- 网络中断不会阻断边缘本地执行；恢复后摘要按序补传且云端不会重复计入历史。
