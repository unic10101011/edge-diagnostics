# 边缘模型运行实现流程

## 〇、模型选型依据（保留实验历史）

| 候选 | 实测吞吐 | 平均输出 token | 结论 |
|---|---|---|---|
| DeepSeek R1-Distill-Qwen-1.5B | 约 0.116 req/s | 约 425（大量中文推理再出 JSON） | 不采用 |
| **Qwen2.5-1.5B-Instruct** | **约 1.44 req/s** | **约 31** | **第一阶段模型** |

换模型的原因：DeepSeek-R1 输出长推理文本，合法 JSON 需要 512 token 上限且吞吐不足；
Qwen2.5-1.5B-Instruct 在 64 token 内稳定输出 3 字段 JSON，实测 JSON 合法率 100%。

以上数值基于 `Qwen2.5-1.5B-Instruct + Transformers(BF16) + RTX 5060 Laptop` 实测
（`tests/performance/benchmark_*.yaml`、`tests/performance/closed_loop/`）。
更换模型后必须复用 `tests/performance/closed_loop/` 重测模型相关参数（推理延迟、
吞吐、显存内存、推理超时、排队等待、支持发送方数、长期稳定性），基础逻辑
（窗口边界、有界队列、熔断状态机、降级闭环、输出契约）无需重新证明。

## 一、总体架构：Windows 主流程 + WSL 模型服务

模型位于 WSL，Windows 边缘程序通过本机 HTTP 调用。正式代码分为两个独立运行环境：

```text
src/edge_model/      Windows 边缘主程序侧（只依赖 Python 标准库）
├─ window_aggregator  1s 窗口聚合（整数纳秒切窗）
├─ model_queue        有界队列 + 三层超时 + 熔断
├─ model_client       HTTP 调用 WSL 模型服务（urllib）
├─ code_fallback      代码规则降级（当前 edge_rule_test_v1）
└─ pipeline           串联并映射窗口诊断 → 每包

src/model_service/    WSL 模型服务侧（torch/transformers）
├─ app                HTTP 服务 /infer /health /readiness（stdlib http.server）
├─ model_runner       Qwen 加载、warmup、推理锁、串行 generate
├─ prompt             提示词（edge-model-prompt/1.0）
└─ output_validator   模型输出校验（edge-model-output/1.0）
```

职责边界：

| 侧 | 负责 | 不负责 |
|---|---|---|
| Windows 侧 | 窗口聚合、有界队列、排队/总超时、熔断、代码降级、每包结果映射 | 不加载 torch/模型 |
| WSL 侧 | 加载 Qwen、warmup、串行 `generate()`、解析校验输出、返回结果 | 不做窗口/队列/降级 |

即使 WSL 模型服务完全不可用，Windows 侧仍能走代码规则完成闭环（健康检查失败 →
`MODEL_UNAVAILABLE` → 代码降级）。这符合"不依赖 vLLM、提高可迁移性"的决定。

## 二、第一阶段实测默认参数

以下参数为**第一阶段实测默认值**（非永久标准），来源：`Qwen2.5-1.5B-Instruct +
Transformers + RTX 5060`，通过 `tests/performance/closed_loop/` 长测/过载/超时
测试验证。

| 参数 | 值 | 语义与依据 |
|---|---|---|
| `window_ms` | 1000 | 1s 窗口，20Hz 感知 → 最多 1 次模型调用/s/发送方。因为 20Hz 逐包调用（20 req/s）远超模型能力（约 1.44 req/s） |
| `max_waiting_requests` | 1 | 队列中「等待中」任务上限，**不含正在推理的 1 条**（语义 = 1 条推理 + 最多 1 条等待） |
| `queue_wait_ms` | 250 | 进入队列后排队超过 250ms 仍未获执行资格 → 代码降级 |
| `inference_timeout_ms` | 1500 | 调用模型服务等待响应超时（对 Qwen 稳态 ~730ms 有余量 ~2x） |
| `total_timeout_ms` | 2000 | 窗口诊断任务创建 → 最终模型或降级结果完成 |
| 熔断阈值 | 5 | 连续失败 5 次 → 熔断，停止继续提交模型请求 |
| 恢复探测周期 | 60s | 熔断后每 60s 放行一次真实推理作为探测，成功即恢复 |
| 稀疏窗口判定 | `min_samples_for_full=15` | 窗口样本 < 15 标记 `WINDOW_SPARSE`，质量置 warning，仍提交 |
| 迟到规则 | drop_and_count | 已关窗口后到达的数据：丢弃并计数（当前唯一实现） |
| 单实例承载 | 1 个持续活跃发送方走模型路线 | 多个发送方仍可接入，但部分窗口进入代码降级；**不表示系统只允许 1 个发送方** |

性能实测摘要（同工具、同种子复现）：

- 单发送方 30 分钟（clean 固定 20Hz 节拍）：1801 窗口，降级率 **0.61%**（10×QUEUE_TIMEOUT
  + 1×QUEUE_FULL），总延迟 p50/p95/p99 = 732/965/1119ms，显存/RSS 无增长，worker 存活。
- 双发送方过载 10 分钟（2 req/s > 1.44 req/s）：吞吐恰好骑在模型能力上限
  （1.42 窗口/s），降级率约 41%（全部为及时的 `QUEUE_FULL`/`QUEUE_TIMEOUT` 降级，
  **无一条任务失败**），队列始终有界（max=1），两发送方近 1:1 公平、无饿死
  （最长连续降级段 ≤6 窗）。
- 低平均负载但高瞬时抖动的压力场景（jitter 调度，含丢包/突发/空窗）：250ms 排队超时下
  降级率约 14%；500ms 时降到约 9% 但交付结果 p95 延迟 +322ms。第一阶段选 250ms：
  常态（固定节拍）降级率仅 0.61%，且边缘场景更重视结果时效性。

## 三、窗口聚合 → 每包结果映射（语义冻结）

外部接口和任务流程保持每包粒度的标识与结果：

```text
发送器 50ms 发包 → 每包 PerceptionResult
→ 进入发送方 1s 窗口
→ 窗口关闭 → 调一次 Qwen（或代码规则）→ 1 个 EdgeResult
→ 该 EdgeResult 映射给窗口内所有数据包
→ 每包摘要保留自己的 packet_id / sequence_number / end_generate_timestamp_ns
```

语义要求：

1. 窗口内数据包**等待窗口关闭**后才完成模型阶段（模型阶段延迟 = 窗口剩余时间 + 推理时间）；
2. 同一窗口内数据包**共享窗口级诊断结果**；
3. 外部接口保持每包原有标识 + 扁平 4 字段 `EdgeResult`，每包各发各的结果；
4. **不得**把窗口级结果描述成"仅根据当前单包得出"——诊断依据是整窗聚合特征。

内部运行记录新增（**不进外部 `EdgeResult`**）：

```text
window_id / window_start_ns / window_end_ns
included_packet_ids（窗口内全部 packet_id 列表）/ sample_count
```

若未来不接受"一窗结果映射到多包"，则当前窗口方案与既有逐包处理流程语义不兼容，
需先解决映射关系再实施。

## 四、窗口聚合

每发送方双缓冲窗口，按到达时刻切 1s 窗口；窗口计算用整数纳秒，避免大单调时间基数
下浮点减法的边界漂移。

```text
20 Hz PerceptionResult ─→ active_window（接收当前秒）
                          ↑ 边界处原子交换
                         closed_window ─→ 聚合 → WindowAggregate
```

- 窗口归属只按到达时刻，不使用 PerceptionResult 内部时间戳；
- 已关窗口后的迟到/乱序到达：丢弃并计数（`late_dropped_count`）；
- 空窗口（sample_count=0）：不调模型，仅记录；
- 稀疏窗口：标记 `quality_status=warning` + `WINDOW_SPARSE`，不伪装正常；
- 特征聚合用均值占位，聚合算法正确性由感知/业务规则另行负责，不在本模块。

## 五、有界模型队列 + 超时 + 熔断

### 队列语义

`max_waiting_requests=1` 只统计等待中的任务，正在推理的 1 条不占额度。

队列满策略：

```text
reject：   新窗口直接走代码降级（记录 QUEUE_FULL）        ← 第一阶段默认
replace：  用新窗口替换尚未开始的旧窗口（旧窗口走降级，正在推理的不打断）
```

### 超时语义（冻结）

```text
queue_wait_ms=250：
    从任务进入模型队列开始，到获得模型执行资格为止。

inference_timeout_ms=1500：
    从开始调用模型服务到等待响应超时。
    属于逻辑超时，不保证终止已经开始的 Transformers generate。

total_timeout_ms=2000：
    从窗口诊断任务创建到最终模型或降级结果完成。
```

注意：`total_timeout_ms` 只与总处理时长比较，**不得**把模型推理超时值与总延迟直接
混用（例如 500ms 排队测试的 P99 总延迟 1370ms，应对比 2000ms 总超时，而不是
1500ms 推理超时）。

### 熔断（Windows 调用侧维护）

```text
连续失败 >= 5 次（超时/模型错误/输出非法）
→ 熔断打开：不再调用模型，一律走 BREAKER_OPEN 降级
→ 每 60s 放行一次真实推理作为恢复探测
→ 探测成功 → 熔断关闭，恢复模型路线
```

限制说明：HTTP 超时后 WSL 中已开始的推理可能仍在执行；推理锁保证同一模型不并发
进入 `generate()`，但**不能处理永久卡死**（若 GPU 硬挂，期间全部窗口降级，直到
streamer 超时后恢复）。第一阶段可接受，已实测熔断打开期间内存无堆积、worker 存活。

## 六、本地模型路线（WSL 服务）

```text
Windows 侧提交窗口聚合输入
→ HTTP POST /infer {"input": WindowAggregate.payload}
→ WSL 加载 Qwen（启动时）+ warmup（2 次短推理，排除首推预热）
→ 推理锁内串行 generate()
→ 解析模型输出 → 校验 edge-model-output/1.0
→ 返回 { valid, edge_result, edge_risk_level, confidence, model_version, ... }
→ Windows 侧封装为统一 EdgeResult
```

启动最小可用性检查：加载模型后跑 2 次短推理（warmup），预热不参与推理超时判定。
warmup 失败或模型未就绪 → `/readiness` 返回未就绪 → Windows 侧走代码降级。

模型版本：`qwen2.5-1.5b-instruct/phase1`。提示词版本 `edge-model-prompt/1.0`
（见 `src/model_service/prompt.py`，已实测合法率 100%；改动提示词必须升版本并重测）。

## 七、代码降级路线

代码路线不是重新实现感知，而是用窗口聚合特征执行固定、可重复的规则，输出与模型
路线结构完全一致的 `EdgeResult`。

正式代码实现：`CodeFallbackRunner` 接口、规则输入校验、规则输出校验、规则版本读取。

**当前规则版本为 `edge_rule_test_v1`**：只证明降级流程可用，**不代表业务规则正确**。
以下内容确认后才能冻结为正式规则版本：

- 使用哪些 `PerceptionResult` / 窗口字段；
- normal / warning / fault 阈值；
- 多特征如何合并；
- 缺失特征如何处理；
- 规则分数算法；
- `confidence` 如何映射；
- 标准测试案例和期望输出。

代码路线要求：不使用随机结果；相同输入必须相同输出；输出结构与模型路线完全一致；
明确标记为规则结果（`model_version = edge_rule_*`）；规则集中配置。

## 八、运行期间的模型异常

```text
模型推理成功 → 返回模型结果

模型不可用 / 超时 / 输出非法
→ 记录 fallback_reason（MODEL_UNAVAILABLE / TIMEOUT / MODEL_OUTPUT_INVALID 等）
→ 当前窗口改走 CodeFallbackRunner
→ 代码路线成功 → 返回统一 EdgeResult

两条路线都失败
→ 返回失败记录（内部标记 CODE_FALLBACK_FAILED，保留原模型路线原因）
→ 该窗口不产出外部 EdgeResult
```

模型出错但代码路线成功时，不应把当前窗口判定为处理失败；必须记录本次降级原因。
熔断打开期间（BREAKER_OPEN）不调用模型，直接降级。

## 九、统一输出（外部接口不变）

两条路线成功时都返回与《边缘部分需要的接口.md》一致的同一个扁平 `EdgeResult`：

| 字段 | 含义 |
|---|---|
| `edge_result` | `normal`、`warning` 或 `fault` |
| `confidence` | `0～1` 有限数；模型路线为未经校准的诊断分数，规则路线为规则分数 |
| `edge_risk_level` | 风险等级 |
| `model_version` | 模型版本；代码降级路线使用带 `edge_rule_` 前缀的规则版本 |

`execution_mode`、`fallback_reason`、`window_id`、`included_packet_ids`、延迟等
属于内部运行记录，不增加到外部任务输出和上云摘要接口。

任务输出映射固定为：

```text
TaskExecutionResult.output.edge_result = EdgeResult.edge_result
TaskExecutionResult.output.confidence = EdgeResult.confidence
TaskExecutionResult.output.edge_risk_level = EdgeResult.edge_risk_level
TaskExecutionResult.output.model_version = EdgeResult.model_version
```

正常上云摘要映射固定为：

```text
summary.edge_inference.edge_result = EdgeResult.edge_result
summary.edge_inference.confidence = EdgeResult.confidence
summary.edge_inference.edge_risk_level = EdgeResult.edge_risk_level
summary.edge_model_version = EdgeResult.model_version
```

## 十、整个流程

```text
Windows 侧启动
→ 校验配置（参数合法性）
→ 检查 WSL 模型服务 /health /readiness
→ 服务就绪 → 模型路线可用；否则仅代码路线

收到感知数据（20 Hz）
→ 进入发送方窗口
→ 窗口关闭 → 聚合 → 有界队列
→ 排队超时/总超时/熔断打开 → 代码降级
→ 模型调用成功 → 模型结果
→ 校验 EdgeResult → 映射给窗口内所有包 → 返回任务编排器
```

## 十一、vLLM 状态

vLLM 因 Blackwell / CUDA / FlashInfer 工具链兼容问题**暂缓**，不是第一阶段依赖。
定位为后续可选性能优化：兼容版本成熟后，用同一套 `tests/performance/closed_loop/`
工具重新 A/B（`serialize_inference=false` 以启用真实批处理），与当前
Transformers 基线比较吞吐/延迟/显存，收益明显才引入。
