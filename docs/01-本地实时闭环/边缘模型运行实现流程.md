# 边缘模型运行实现流程

## 一、目标与范围

本流程负责将感知模块生成的结构化结果交给边缘模型完成推理，并输出统一的边缘诊断结果。范围包括模型准备、输入转换、模型推理、结果校验和异常处理，不包含原始数据采集、特征提取、云端复核及模型在线更新。

## 二、总体流程

```text
接收 PerceptionResult
→ 检查模型运行状态
→ 转换并校验模型输入
→ 执行边缘推理
→ 解析并校验模型输出
→ 封装 EdgeResult
→ 返回任务编排器
```

## 三、实现步骤

### 步骤1：准备模型运行环境

```text
读取模型配置和模型文件
→ 初始化推理运行时并加载模型
→ 校验模型版本和输入输出约定
→ 执行一次预热推理
→ 检查通过后将模型状态设为READY
```

重点检查：

- 模型文件存在且能够正常加载；
- 模型版本与当前部署配置一致；
- 输入特征顺序、数据类型和形状与模型要求一致；
- 输出能够转换为`edge_result`、`confidence`和`edge_risk_level`；
- 预热推理能够产生结构正确、数值有限的结果。

任一步骤失败时：

```text
释放已创建的模型资源
→ 模型状态设为UNAVAILABLE
→ 记录失败阶段和具体原因
→ 不接受后续模型推理
```
| 字段 | 含义 |
|---|---|
| `state` | 当前模型状态 |
| `model_version` | 已加载模型版本；未成功加载时为`null` |
| `ready_at_ns` | 模型进入可用状态的时间；未就绪时为`null` |
| `error_code` | 准备失败错误码；正常时为`null` |
| `error_message` | 具体失败原因；正常时为`null` |

state取值：
INITIALIZING  正在加载和检查模型
READY         模型可接受推理
UNAVAILABLE   模型准备失败，不可推理

当前阶段假设模型在任务开始前已经成功加载，因此准备失败应表现为边缘服务未就绪，不进入数据包处理流程。此次未修改文档。

### 步骤 2：接收感知结果并确认调用条件

接收任务编排器传入的PerceptionResult
→ 确认上游感知处理成功
→ 确认payload不为空并属于当前数据包
→ 进入模型输入转换

接收任务编排器传入的完整PerceptionResult，确认上游感知处理成功、结果非空且属于当前数据包。满足条件后进入模型输入转换，不重复执行原始数据校验、质量判断和特征完整性检查。

### 步骤 3：转换模型输入

按照模型约定整理特征顺序、数据类型和输入形状，形成独立的模型输入对象。转换过程只读取感知结果，不应修改上游数据。

### 步骤 4：执行模型推理

调用已就绪的边缘模型完成单次推理，并记录必要的运行耗时和模型标识。推理过程应设置超时并捕获运行时异常，避免单次失败影响服务进程和其他任务。

### 步骤 5：解析并校验模型输出

将模型原始输出转换为业务可识别的诊断信息，并检查输出结构、数值范围和必需字段。缺失、越界或无法解析的输出均视为模型输出无效。

### 步骤 6：封装统一结果

将诊断结论、置信信息、模型标识和必要的关联字段封装为统一的 `EdgeResult`。结果中只保留后续流程需要的信息，不携带模型内部临时对象。

### 步骤 7：返回结果并完成收尾

把成功结果或标准化失败信息返回任务编排器，同时释放本次推理产生的临时资源并记录必要日志。模型运行模块不直接更新任务最终状态，由任务编排器统一处理。

## 四、异常处理原则

- 模型未加载或状态不可用时，返回固定的模型加载错误。
- 输入转换失败时，不进入模型推理。
- 推理异常或超时时，只终止当前数据包的处理。
- 模型输出不合法时，不生成部分成功结果。
- 所有内部异常统一转换为稳定的错误码，并保留必要的本地排错信息。

## 五、最小验收标准

- 合法的 `PerceptionResult` 能够稳定生成统一的 `EdgeResult`。
- 模型未加载时能够返回明确且固定的错误信息。
- 非法输入和非法模型输出均能被拒绝，不会产生误导性结果。
- 推理异常或超时不会导致服务进程退出，也不会影响后续任务。
- 模型运行前后的上游感知结果保持不变。
