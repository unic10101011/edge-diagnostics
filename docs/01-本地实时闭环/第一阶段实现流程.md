# 第一阶段实现流程：边缘本地实时闭环

## 1. 阶段目标

第一阶段只实现一条可以独立运行、可以验证的边缘本地实时处理链：

```text
调度器下发任务
→ 边缘接收任务并确认
→ 数据发送器发送原始数据包
→ 边缘完成任务与数据包匹配
→ 数据校验
→ 高采样率原始包写入环形缓存
→ 生成降采样计算副本
→ 感知模块完成预处理和特征提取
→ 边缘模型完成推理
→ 边缘向调度器返回任务执行结果
```

第一阶段完成后，应能够证明：

1. 调度任务与原始数据包可以正确关联。
2. 合法数据可以完成整个处理链并返回边缘诊断结果。
3. 非法数据会在校验阶段被拒绝，不进入缓存、降采样、感知和模型。
4. 任一处理阶段失败时，任务都能返回统一的失败结果。
5. 降采样和特征计算不会修改环形缓存中的原始数据。

## 2. 第一阶段范围

### 2.1 本阶段实现

1. 公共数据结构和错误码。
2. 调度任务接入。
3. 原始数据包接入。
4. 任务与数据包匹配。
5. 数据严格校验。
6. 高采样率原始数据环形缓存。
7. 高频信号降采样。
8. 数据预处理、质量判断和特征提取。
9. 边缘模型加载、推理和输出校验。
10. 任务状态管理。
11. 向调度器返回任务确认和最终执行结果。
12. 支撑排错所需的基础本地日志。

### 2.2 本阶段不实现

以下功能分别留到后续阶段：

- 每包摘要持久化和可靠上云；
- 摘要批量发送、云端确认和断网补传；
- 云端原始上下文请求；
- 当前包、前置包和后置包的原始数据上传；
- 节点资源与网络状态周期上报；
- 云端规则、配置和模型在线更新；
- 前端展示和云端数据库写入。

第一阶段可以预留摘要生成所需的数据对象，但不启动摘要上传线程，也不依赖云端才能完成本地任务。

## 4. 正常处理流程

### 步骤1：任务基本校验

任务编排器检查：

- `task_id` 是否存在；
- `target_edge_node_id` 是否为本节点；
- `task_type` 是否为支持的类型；
- `input_ref` 是否完整；
- 是否存在内容冲突的重复任务。

校验通过后返回 `ACCEPTED`，否则返回 `REJECTED` 和固定 `reason_code`。

### 步骤2：原始数据接入

数据接入模块负责：

- 解析外部数据结构；
- 限制请求体和数组规模；
- 提取包身份；
- 登记待匹配原始包；
- 通知任务匹配器。

此时只做防止系统无法解析或内存失控的接入检查，完整的业务校验在下一步骤执行。

### 步骤3：数据严格校验

校验内容包括：

1. 必要字段和字段类型；
2. 六路序列结构；
3. 采样率和采样点数；
4. 数组是否为空；
5. NaN、Inf和非数值；
6. 数值合理范围（已配置硬量程的通道才执行范围校验，本阶段未取得硬量程时跳过）；
7. 各通道采样窗口时长；
8. 时间戳；
9. 包身份冲突；
10. 序号重复、跳号和倒退。

校验成功输出 `ValidatedRawPacket`。

校验失败立即停止后续处理，并生成统一错误结果：

```text
status = FAILED
error_code = VALIDATION_FAILED 或具体校验错误码
output = null
```

### 步骤4：写入高采样率环形缓存

缓存模块必须：

1. 将完整包复制为独立对象；
2. 保留原始采样率、采样点数、单位和时间字段；
3. 将同一包的所有通道原子写入；
4. 按 `sender_id`、`packet_id`、`sequence_number` 和时间戳建立索引；
5. 只淘汰最早的完整包。

缓存成功后，才允许进入降采样。

如果缓存写入失败，本任务停止，避免出现“模型已处理但需要复核时找不到原始包”的不一致状态。

### 步骤5：生成计算副本并降采样

所有计算只能作用于独立副本，不能修改缓存对象。

处理规则：

| 通道 | 原始采样率 | 分析采样率 | 处理 |
|---|---:|---:|---|
| 振动 | 64 kHz | 16 kHz | 抗混叠滤波后降采样 |
| 电流1 | 64 kHz | 16 kHz | 抗混叠滤波后降采样 |
| 电流2 | 64 kHz | 16 kHz | 抗混叠滤波后降采样 |
| 转速 | 4 kHz | 4 kHz | 保持不变 |
| 转矩 | 4 kHz | 4 kHz | 保持不变 |
| 径向载荷 | 4 kHz | 4 kHz | 保持不变 |
| 温度 | 单值 | 单值 | 保持不变 |

降采样完成后检查：

- 三路高频信号输出长度是否均为800点；
- 采样窗口是否仍为50 ms；
- 结束时间是否与原始包一致；
- 是否出现NaN或Inf。

### 步骤6：感知处理

感知模块依次执行：

```text
数据类型统一
→ 时域与频域计算副本分离
→ 频域分析前去均值
→ 加分析窗
→ 质量判断
→ 时域特征
→ 频域特征
→ 工况统计
→ 组装 PerceptionResult
```

质量问题分为两类：

- 结构性或严重问题：停止模型推理；
- 不影响继续处理的问题：设置 `warning` 和质量标志，继续推理。

### 步骤7：边缘模型推理

模型运行时负责：

1. 确认模型已经加载；
2. 将 `PerceptionResult` 转换成模型输入；
3. 调用边缘模型；
4. 捕获加载失败、推理异常和超时；
5. 解析模型输出；
6. 校验结果字段和取值范围；
7. 生成统一 `EdgeResult`。

模型只接收结构化特征、工况和数据质量信息，默认不直接接收高采样率原始波形。

### 步骤8：封装并返回任务结果

任务编排器将以下信息合并：

```text
TaskDispatch
+ input_ref
+ EdgeResult
+ 处理时间
+ edge_node_id
```

形成 `TaskExecutionResult` 并返回调度器。

任务成功后释放待匹配记录和运行时临时对象，但不删除环形缓存中的原始包。

## 5. 异常处理

建议第一阶段至少定义以下错误码：

| 阶段 | 错误码 | 含义 |
|---|---|---|
| 任务接入 | `TARGET_NODE_MISMATCH` | 任务目标不是当前节点 |
| 任务接入 | `UNSUPPORTED_TASK_TYPE` | 不支持该任务类型 |
| 任务接入 | `TASK_CONFLICT` | 同一任务标识对应不同内容 |
| 数据匹配 | `INPUT_WAIT_TIMEOUT` | 等待对应原始包超时 |
| 数据匹配 | `INPUT_REFERENCE_MISMATCH` | 任务引用与原始包身份不一致 |
| 数据校验 | `MISSING_CHANNEL` | 缺少必要通道 |
| 数据校验 | `INVALID_SAMPLE_RATE` | 采样率不合法 |
| 数据校验 | `INVALID_SAMPLE_COUNT` | 采样点数不合法 |
| 数据校验 | `EMPTY_VALUES` | 采样数组为空 |
| 数据校验 | `NON_FINITE_VALUE` | 存在NaN或Inf |
| 数据校验 | `VALUE_OUT_OF_RANGE` | 数值超出已配置的允许范围（未配置硬量程时该检查停用） |
| 数据校验 | `CHANNEL_DURATION_MISMATCH` | 通道覆盖时长不一致 |
| 数据校验 | `INVALID_TIMESTAMP` | 时间戳不合法 |
| 缓存 | `RAW_CACHE_WRITE_FAILED` | 原始包写入环形缓存失败 |
| 降采样 | `DOWNSAMPLING_FAILED` | 滤波或降采样失败 |
| 感知 | `PERCEPTION_FAILED` | 预处理或特征提取失败 |
| 模型 | `MODEL_LOAD_FAILED` | 模型未能正确加载 |
| 模型 | `MODEL_INFERENCE_FAILED` | 模型推理异常 |
| 模型 | `MODEL_OUTPUT_INVALID` | 模型输出结构或取值非法 |
| 全流程 | `EXECUTION_TIMEOUT` | 整体处理超过允许时间 |

所有异常最终都由任务编排器转换为统一的 `TaskExecutionResult`，内部模块不直接拼装外部响应。

## 6. 数据所有权与不可变约束

为了避免缓存、降采样和感知之间互相修改数据，统一采用以下规则：

```text
RawSensorPacket
→ 校验
→ 缓存专用不可变副本
→ 计算专用副本
→ DownsampledPacket
→ PerceptionResult
→ EdgeResult
```

必须满足：

1. 环形缓存对象写入后不可修改。
2. 降采样只处理计算副本。
3. 感知模块不能反向修改降采样输入。
4. 模型运行时不能修改感知结果。
5. 对外结果只引用身份字段和计算结果，不直接暴露内部可变对象。

## 7. 实现顺序

按以下顺序开发，每一步都先通过独立测试再继续：

### 第一步：公共契约

定义外部接口对象、内部数据对象、枚举和错误码。

验收：

- 合法示例能够解析；
- 缺少必要字段时能够给出明确错误；
- 成功和失败任务结果满足统一结构。

### 第二步：任务接入和数据匹配

实现任务注册表、待匹配数据区和任务状态机。

验收：

- 任务先到可以等待数据；
- 数据先到可以等待任务；
- 身份不一致不会错误匹配；
- 重复消息不会重复执行任务。

### 第三步：校验和环形缓存

实现严格校验和完整原始包原子缓存。

验收：

- 合法包可以写入；
- 非法包不会写入；
- 缓存淘汰按完整包进行；
- 读取的数据与写入时完全一致。

### 第四步：降采样和感知

实现计算副本、降采样、质量判断和特征提取。

验收：

- 64 kHz、3200点正确变为16 kHz、800点；
- 采样窗口和结束时间保持不变；
- 特征结果不存在NaN和Inf；
- 原始缓存内容没有被修改。

### 第五步：边缘模型运行时

实现模型加载、输入转换、推理、输出解析和错误处理。

验收：

- 合法感知结果能够生成统一 `EdgeResult`；
- 模型未加载时先进入代码替代路线；代码路线成功则仍生成合法`EdgeResult`，代码路线也失败才返回`MODEL_LOAD_FAILED`；
- 非法模型输出被拒绝并进入代码替代路线；代码路线成功则任务继续，代码路线也失败才返回`MODEL_OUTPUT_INVALID`；
- 模型推理异常时进入代码替代路线；代码路线也失败才返回`MODEL_INFERENCE_FAILED`；
- 推理异常不会导致服务进程退出。

### 第六步：端到端闭环

连接所有模块并返回任务执行结果。

验收：

- 合法任务完整成功；
- 校验失败任务正确终止；
- 本地模型和代码替代路线都失败时，任务正确终止；
- 等待数据超时任务正确终止；
- 每个任务只有一个最终状态；
- 不依赖云端服务也能完成边缘本地执行。

## 8. 第一阶段最终验收场景

至少覆盖以下场景：

| 场景 | 预期结果 |
|---|---|
| 任务先到、合法数据后到 | 匹配成功并返回 `SUCCEEDED` |
| 数据先到、合法任务后到 | 匹配成功并返回 `SUCCEEDED` |
| 目标节点错误 | 返回 `REJECTED` |
| 不支持的任务类型 | 返回 `REJECTED` |
| 原始包缺少必要通道 | 返回 `FAILED`，不写缓存 |
| 原始包采样点数错误 | 返回 `FAILED`，不执行降采样和模型 |
| 原始包包含NaN或Inf | 返回 `FAILED`，不写缓存 |
| 任务引用与数据身份不一致 | 不匹配，最终失败或超时 |
| 重复发送同一任务 | 不重复执行 |
| 同一包号对应不同内容 | 返回冲突错误 |
| 环形缓存写入失败 | 返回 `FAILED`，不执行后续处理 |
| 降采样失败 | 返回 `FAILED`，原始包仍保留在缓存 |
| 感知失败 | 返回 `FAILED`，不执行模型 |
| 模型加载失败，代码替代路线成功 | 返回`SUCCEEDED`和规则生成的`EdgeResult`，内部记录`MODEL_LOAD_FAILED` |
| 模型加载失败，代码替代路线也失败 | 返回`FAILED`和`MODEL_LOAD_FAILED` |
| 模型推理异常，代码替代路线成功 | 返回`SUCCEEDED`和规则生成的`EdgeResult`，内部记录`MODEL_INFERENCE_FAILED` |
| 模型推理异常，代码替代路线也失败 | 返回`FAILED`和`MODEL_INFERENCE_FAILED` |
| 模型输出不合法，代码替代路线成功 | 返回`SUCCEEDED`和规则生成的`EdgeResult`，内部记录`MODEL_OUTPUT_INVALID` |
| 模型输出不合法，代码替代路线也失败 | 返回`FAILED`和`MODEL_OUTPUT_INVALID` |
| 等待原始包超时 | 返回 `TIMEOUT` |

## 9. 第一阶段完成定义

同时满足以下条件，才认为第一阶段完成：

- 外部任务和原始数据接口已经固定并能够校验；
- 当前理想场景不启用超时；
- 主处理链各模块具有明确输入输出；
- 有效包能够稳定返回边缘诊断结果；
- 无效包不会越过校验边界；
- 高采样率原始包先缓存、后降采样；
- 环形缓存数据不会被计算过程修改；
- 感知与边缘模型职责分离；
- 所有内部错误都能映射成统一任务失败结果；
- 端到端测试不依赖云端、前端和摘要上传功能。
